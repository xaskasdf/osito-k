# Certificate Manager

Osito-K loads system trust anchors from `/tls/ca-roots.bin` after mounting the
root filesystem. The bundle is generated by
`tools/certmgr/build-root-store.py`; roots are data, not certificates compiled
into the kernel. The manager verifies the bundle hash and each root record,
then builds indexes for certificate fingerprints, subject names, and SKI.

`CertGetCertificateChain` constructs a process-owned chain from the supplied
certificate and additional store. It verifies signatures, validity windows,
basic constraints, key usage, EKU, and exact DER membership of the final trust
anchor. A matching public key alone does not establish trust. Root EKU policy
is honored when the caller requests a usage.

Revocation checks are authenticated before publication. OCSP validation checks
the CertID, responder identity, delegated responder EKU, signature, status, and
freshness. CRL validation checks issuer relationship, `cRLSign`, signature,
validity, and serial status. Verified results enter a bounded in-memory cache;
CRLs are persisted through a temporary OsitoFS3 file followed by rename.

Crypt32 chain construction never performs network I/O while holding an
application call. A cache miss returns Windows-compatible unknown/offline trust
bits rather than silently trusting or rejecting the certificate. Network
work is copied into a bounded 16-entry queue and deduplicated by leaf and issuer
fingerprints. A kernel worker may later populate the cache; responder failures
receive a short retry backoff.

Build a bundle with:

```sh
python3 tools/certmgr/build-root-store.py --help
```

Run deterministic parser fixtures with:

```sh
bash tools/certmgr/test-revocation.sh
```
